Задача 0 — ознакомительная работа

Общая для всех студентов
Цель работы — познакомиться с агентным рабочим процессом до начала индивидуальных исследовательских заданий.

Практическое задание

  1. Клонировать с GitHub небольшой учебный проект по физике или машинному обучению.
  2. Попросить агента только исследовать структуру проекта: основные файлы, зависимости, точки входа, способ запуска и тестирования. На этом этапе агент не должен изменять код.
  3. Попросить агента провести аудит научной корректности: проверить физические предположения, размерности и единицы, формулы, используемые модели, обработку данных и наличие очевидных методических ошибок.
  4. При помощи агента создать собственный небольшой проект по шаблону, описанному ранее в курсе: с понятной структурой, воспроизводимым запуском, зависимостями, проверками и краткой документацией.

Минимальный результат

Итогом работы должен быть один файл .md, в котором кратко зафиксированы: выбранный исходный проект, его структура, основные замечания научного аудита, а также описание созданного собственного проекта и способа его запуска.

Присылать этот файл преподавателю отдельно не требуется. Он нужен как рабочий результат ознакомительной работы и как подтверждение того, что студент умеет использовать агента для исследования, проверки и создания проекта.

Методы для задачи 1

    Проверка обобщающей способности

    Что должно быть получено минимально

      В отчёте обязательно: сводная таблица моделей, набора признаков, способа масштабирования, гиперпараметров и метрик; график «измеренное — предсказанное»; график остатков; зависимость ошибки проверки от сложности модели или силы регуляризации; коэффициенты и оценка их устойчивости; отдельный результат проверки на отложенном физическом режиме или экстраполяции.

      Обязательный исследовательский результат

      Последний обязательный пункт: воспроизводимый отчёт. Итоговый PDF-отчёт должен быть результатом выполнения воспроизводимого скрипта сборки, а не документом, в который рисунки, таблицы и численные результаты перенесены вручную. Из исходных данных одной документированной командой (например, python run.py или make report) должны автоматически выполняться загрузка или чтение исходных данных, предобработка, разбиение выборки, обучение и выбор моделей, расчёт метрик, построение всех рисунков и таблиц и сборка файла report.pdf. Случайные состояния должны быть зафиксированы, а зависимости проекта — явно указаны. Проверяющий должен иметь возможность удалить каталог с производными результатами и заново получить report.pdf, таблицы и рисунки одной указанной командой. Текст отчёта может храниться в шаблоне Markdown/Typst/LaTeX, но все численные результаты, таблицы и рисунки должны подставляться или генерироваться этим скриптом; ручное исправление результатов в итоговом PDF не допускается. Структуру и оформление отчёта выполнить по ГОСТ 7.32-2017 «Отчёт о научно-исследовательской работе. Структура и правила оформления».
